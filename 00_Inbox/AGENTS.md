# Vault運用ルール（AI・人間共通）

## 対応履歴への転記ルール

デイリーから `Notion/顧客情報/顧客管理/<顧客名>/対応履歴/` へ転記する際の形式。
既存の対応履歴（例：テレック吉安の `インターネット不調1.md`）に合わせること。

- 対象はその顧客への対応・メモ節のみ。デイリー全体や他話題は持ち込まない
- 要約・省略禁止。全要素を清書する（事実・数量・原文の言い回しを落とさない）
- ナビ用のリンク行（例：`対応履歴を確認`）は対応内容ではないため転記しない
- 1行目：`電話：●●さま` / `メール：●●さま` / `面談：●●さま` / `同行：△△さん` の形式で、その日の行動に関与した人物が分かるように書く（チャネル＋氏名）
- 2行目：概要を1行で書く
- 3行目以降：`【見出し】` を置き、次行からその内容を書く。必要なことを全て書き入れる
- frontmatter は下記の形にする（`base` は素名リンクにせずフルパスで書く。`notion-id` は新規作成時には付けない）
  ```yaml
  ---
  base: "[[Notion/顧客情報/顧客管理/<顧客名>/対応履歴/対応履歴.base]]"
  日付: YYYY-MM-DD
  内容: |-
    （上記形式の本文）
  ---
  ```
- ファイル名は `YYYY-MM-DD 件名.md` とする（既存の `○○ 1` 式の重複命名は使わない）
- 本文末に出典デイリーを付記する（例：`出典：[[2026-09-07]]`）
- `.base` ファイルには Markdown を追記しない（`.base` は YAML のみ有効。文章は `.md` に書く）

## 計画書・訪問準備文書の出力ルール

- 計画案（提案内容・前提）→留意点（要注意事項）→タスク（事前・現地確認・事後）の順にセクションを配置する
- サマリ（対応履歴・環境メモ）は末尾に配置する
- リンク正常化メモ等のメタ情報は最後に配置する
- 基本情報（日時・先方・住所・同行/連携）は文書先頭に配置し、各セクションから参照できるようにする
