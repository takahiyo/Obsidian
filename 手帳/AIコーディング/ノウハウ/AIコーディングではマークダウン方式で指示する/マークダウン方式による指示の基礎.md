AIコーディング向けに**「指示が誤解されにくく、差分事故を起こしにくい」Markdown記法**に限定して整理します。

装飾目的ではなく、**構造と拘束条件を伝えるための記法**に絞っています。

---

## 1. 見出し（`#` / `##` / `###`）

**用途**

- 役割分担
- 要件の階層化
- 「ここからここまでが同じ文脈」を明示

```markdown
## 目的
## 制約条件
## 修正内容
### JS側
### CSS側
```

**ポイント**

- AIは見出し単位で思考を切り替える
- 指示・制約・実装を混在させない

---

## 2. 箇条書き（ / ）

**用途**

- 制約条件
- 必須ルール
- やってはいけないこと

```markdown
- ハードコーディング禁止
- config.js に集約すること
- 既存仕様は変更しない
```

**ポイント**

- 「すべて満たす条件」として強く解釈されやすい
- 長文で書くより拘束力が高い

---

## 3. 番号付きリスト（`1.` `2.`）

**用途**

- 実行順序
- 処理フロー
- 手順固定の指示

```markdown
1. config.js を新規作成
2. 定数を移動
3. 呼び出し側を修正
```

**ポイント**

- 順序を勝手に入れ替えにくくなる
- 「途中を省略しない」効果がある

---

## 4. コードブロック（```）

**用途**

- 変更対象の明示
- Before / After の厳密な区別
- コピペ前提の指示

````markdown
```js
// 変更前
const LIMIT = 10;
````

```jsx
// 変更後
import { LIMIT } from './config.js';
```

````

**ポイント**
- **絶対に文章と混ぜない**
- コメントで「変更前／変更後」を必ず明示

---

## 5. インラインコード（`` ` ``）

**用途**
- ファイル名
- 変数名
- 関数名

```md
`config.js` に定数を集約する
`initApp()` の挙動は変更しない
````

**ポイント**

- AIが「コード要素」として認識する
- 文章中の曖昧さを防げる

---

## 6. 強調（`*太字**`）

**用途**

- 破ると致命的な制約
- 最重要ルール

```markdown
**既存の仕様は一切変更しない**
```

**ポイント**

- 使いすぎると効かなくなる
- 1セクションに1〜2個まで

---

## 7. 引用（`>`）

**用途**

- 背景説明
- 補足条件
- 実装理由（変更不要な文脈）

```markdown
> この処理は後方互換のため残しています
```

**ポイント**

- AIは「参考情報」として扱う
- 実装指示と混ざらない

---

## 8. セクション分離の定型テンプレ（実戦向け）

```markdown
## 目的

## 変更してよい範囲

## 変更してはいけない範囲

## 実装指示
### JS
### CSS

## 出力条件
```

この構造だけで、

- 勝手なリファクタ
- 不要な最適化
- 仕様破壊

をかなり抑制できます。

---

## 最重要まとめ（AIコーディング視点）

- Markdownは**装飾ではなく制御**
- 見出し＝思考の区切り
- 箇条書き＝拘束条件
- コードブロック＝絶対領域

AIに「考えさせる」のではなく、

**考える範囲を Markdown で封じる**のがコツです。
